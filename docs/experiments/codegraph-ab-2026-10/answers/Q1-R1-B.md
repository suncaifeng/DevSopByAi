## Cross-function implications and limits

- **Inference from the call order and loop detector:** `main()` appends the current result to history before routing. The stuck-loop detector then takes the last two history errors and appends the current error again ([main.py:40](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-B-attempt1/main.py:40), [routing_system.py:142](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-B-attempt1/routing_system.py:142)). Thus two consecutive identical errors can satisfy its three-item check. A detected loop sends test/spec/validation errors to repair-or-regenerate and other repeated errors to fatal ([routing_system.py:146](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-B-attempt1/routing_system.py:146), [routing_system.py:157](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-B-attempt1/routing_system.py:157), [routing_system.py:165](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-B-attempt1/routing_system.py:165)).
- **Inference from the repair path:** although `state.current_dsl` is initialized, the visible repair branch does not replace `execution_input.dsl`, and the adapter serializes that input DSL on each call. A `REPAIR_SPEC` continuation therefore re-executes with the same DSL in this checked-in implementation ([main.py:26](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-B-attempt1/main.py:26), [main.py:58](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-B-attempt1/main.py:58), [codex_run.py:138](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-B-attempt1/codex_run.py:138)).
