### Inferences and runtime uncertainty

- **Adding only the literal does not make `run_codex` emit it.** Its subprocess path still calls the existing classifier, whose return branches do not include `MCP_START_ERROR`. The new value could be carried if another caller constructs an `ExecutionResult` with it, or if classification/emission is separately changed.
- **How an MCP startup message is classified depends on its text.** For example, output containing a recognized environment token may become `ENV_ERROR`; output containing a recognized runtime token may become `CODEX_ERROR`; output matching none of the checks becomes `UNKNOWN`. The source does not establish the wording or source of MCP startup failures.
- A direct call to `route_decision` with `status="SUCCESS"` returns a success route before inspecting the error type. In the `main` flow, however, `validate_execution_result` runs first and rejects success paired with any non-`NONE` error type.
