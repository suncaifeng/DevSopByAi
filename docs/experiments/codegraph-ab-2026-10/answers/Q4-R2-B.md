## Source-confirmed flow

`ExecutionInput.metadata` is a general dictionary; timeout configuration is separate from `RunPolicy` ([contracts.py:84](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/contracts.py:84), [contracts.py:71](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/contracts.py:71)). In `codex_run.py`, `_timeout_seconds` reads `metadata["timeout_seconds"]`, defaulting to **300 seconds**. It accepts only a positive `int`; a missing or nonmatching value falls back to 300. Input validation checks policy limits but does not validate this metadata value ([codex_run.py:166](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:166), [codex_run.py:168](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:168), [contracts.py:200](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/contracts.py:200)).

The same metadata is also written into the temporary spec JSON, but the code applies the subprocess timeout directly from `ExecutionInput`, not by reading it back from that JSON ([codex_run.py:148](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:148)).

If the call raises `subprocess.TimeoutExpired`, the handler constructs a failed `ExecutionResult` with `exit_code=-1`, `error_type="CODEX_ERROR"`, summary “Codex execution timed out,” captured output logs, and `tests.ran=False`. The result’s raw data records `timeout_seconds` by calling `_timeout_seconds` again rather than saving the exact value passed to `run` ([codex_run.py:77](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:77), [codex_run.py:82](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:82), [codex_run.py:93](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:93)). The result contract permits a failed result with a nonzero exit code, so `-1` passes that check ([contracts.py:231](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/contracts.py:231)). The `finally` block attempts to remove the temporary spec file ([codex_run.py:121](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:121)).

That exception path **sets `CODEX_ERROR` directly**; it does not call `classify_error`. For a subprocess that returns normally with a nonzero exit code, `classify_error` classifies its output text instead. Its earlier test, spec-conflict, validation, and environment checks can take precedence over its later `"timeout"` check ([codex_run.py:53](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:53), [codex_run.py:180](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:180), [codex_run.py:183](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:183), [codex_run.py:202](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/codex_run.py:202)).

## Routing, retries, and stuck-loop handling

`main` saves each result in history before passing it to the router ([main.py:40](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/main.py:40), [main.py:42](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/main.py:42)). For a timeout’s `CODEX_ERROR`, the router first checks for blocking DSL state, then checks for a stuck loop, and only afterward reaches the ordinary `CODEX_ERROR` retry branch. Blocking DSL state therefore routes to `REPAIR_SPEC` before timeout retry logic; otherwise, a non-stuck `CODEX_ERROR` routes to `RETRY_CODEX` when both the cycle and retry budgets permit it, or to `FATAL` ([routing_system.py:42](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/routing_system.py:42), [routing_system.py:51](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/routing_system.py:51), [routing_system.py:86](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/routing_system.py:86), [contracts.py:270](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/contracts.py:270)).

**Source-based inference:** `STUCK_LOOP_WINDOW` is 3, and the detector takes the last two history errors and appends the current error ([routing_system.py:16](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/routing_system.py:16), [routing_system.py:142](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/routing_system.py:142)). Because `main` already appended that current result, the current error is counted twice on the normal `main` path. Thus, two consecutive results with the same error type can satisfy the nominal three-error check. For repeated `CODEX_ERROR`, `_route_stuck_loop` returns `FATAL`: its repair/regenerate cases cover test failures, spec conflicts, and validation errors, not `CODEX_ERROR` ([routing_system.py:152](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/routing_system.py:152)). So a second consecutive timeout can be fatal before the ordinary retry branch, even with retry budget remaining.

## Max-cycle stop

The loop runs while `total_cycles < max_total_cycles`; the defaults are 10 cycles and 2 Codex retries ([main.py:29](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/main.py:29), [contracts.py:72](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/contracts.py:72)). A retry increments both counters and continues the loop ([main.py:91](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/main.py:91), [main.py:97](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/main.py:97)). If that increment reaches the cycle limit, the loop exits, prints “Max total cycles reached,” and returns without another subprocess invocation ([main.py:75](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/main.py:75)). A timeout routed to `FATAL` instead returns through the fatal branch, without reaching that max-cycle message ([main.py:69](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q4-R2-B-attempt1/main.py:69)).
