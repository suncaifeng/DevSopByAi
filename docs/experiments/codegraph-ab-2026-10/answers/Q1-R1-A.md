## Call path

**Source confirmed:** the repository’s callable entry point is `main.main(execution_input)`. It takes an already constructed `ExecutionInput`; the checked-in Python source shows no CLI/API wrapper or input builder. Running `main.py` directly raises `SystemExit` with a message directing callers to build an input and call `main` ([main.main](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:21), [direct-execution guard](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:118)). ## Validation and execution

`main` first calls `validate_execution_input`; any errors raise `ValueError` before state creation or dispatch ([main.py:22](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:22)). The contract requires validator verdict `PASS`, readiness `true`, a nonempty DSL and workspace root, and valid cycle/retry/repair limits. DSL validation checks required sections and consistency among compilation status, repair status, blockers, unresolved issues, and blocking markers ([contracts.py:152](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/contracts.py:152), [contracts.py:200](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/contracts.py:200)). The visible validation does not check `WorkspacePolicy.allowed_paths` or `denied_paths`; the adapter uses `workspace.root` as the subprocess working directory ([contracts.py:63](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/contracts.py:63), [codex_run.py:40](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:40)).

Inside the cycle loop, `main` calls `run_codex`, validates the returned result, stores it as `last_execution`, appends it to history, then calls and validates `route_decision` ([main.py:29](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:29), [main.py:36](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:36)). Result validation checks status/error-type and exit-code consistency, plus that a reported test run has a boolean outcome. Route validation checks confidence, reason, and whether spec-changing routes set `requires_spec_change` ([contracts.py:231](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/contracts.py:231), [contracts.py:252](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/contracts.py:252)).

`run_codex` writes a temporary JSON spec containing the DSL, selected validator fields, and metadata; it then builds a command and calls `subprocess.run` with captured text output, the workspace root as `cwd`, and a timeout ([codex_run.py:22](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:22), [codex_run.py:126](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:126), [codex_run.py:158](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:158)). A nonempty `metadata["codex_command"]` list is stringified and has `--spec <path>` appended; otherwise the command is `codex exec --spec <path>`. A positive integer `timeout_seconds` overrides the 300-second default ([codex_run.py:158](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:158), [codex_run.py:166](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:166)).

## Result and evidence capture

For a normal subprocess return, exit code zero maps to `SUCCESS`/`NONE`; a nonzero code maps to `FAILED` and is classified from lowercase stdout and stderr. The classifier checks test terms, spec conflict terms, validation terms, environment terms, then runtime-error terms, falling back to `UNKNOWN` ([codex_run.py:48](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:48), [codex_run.py:180](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:180)).

The result includes compacted stdout/stderr logs, inferred test status, and a `raw` dictionary with run ID, duration, command, spec path, outputs, and cycle/version fields. `changed_files` is always an empty list in these result paths. A timeout returns `CODEX_ERROR` with exit code `-1`; a missing command returns `ENV_ERROR` with exit code `127`. The temporary spec is removed in `finally` ([codex_run.py:56](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:56), [codex_run.py:77](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:77), [codex_run.py:103](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:103), [codex_run.py:121](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:121)).

**Evidence limit:** the visible path returns results in memory and appends them to `state.history`; it has no separate persistent result writer. Test outcomes are inferred from output text, not from a separately invoked test runner ([codex_run.py:229](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/codex_run.py:229)).

## Routing and exit behavior

`route_decision` routes `SUCCESS` first. For failures, DSL blockers or blocking markers trigger `REPAIR_SPEC` before stuck-loop or error-type handling. Otherwise, repeated errors are checked, then error-specific branches apply: `TEST_FAILURE` may retry or repair/fail; `SPEC_CONFLICT` may repair or regenerate; `VALIDATION_ERROR` may repair or fail; `CODEX_ERROR` may retry or become fatal; `ENV_ERROR` and unknown types become fatal ([routing_system.py:19](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/routing_system.py:19), [routing_system.py:33](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/routing_system.py:33), [routing_system.py:54](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/routing_system.py:54)).

`main` returns the state on `SUCCESS`, `REGENERATE_SPEC`, `ASK_USER`, or `FATAL`; unknown routes raise `ValueError`. Retry increments retry and cycle counters. Repair increments repair, spec-version, and cycle counters, then continues; the source comments that the repair hook is not implemented. Reaching the cycle limit also returns the state ([main.py:48](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:48), [main.py:91](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:91), [main.py:102](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:102)).

**Inference from call ordering:** because `main` appends the current result before routing, and `_detect_stuck_loop` then reads recent history and appends that same error again, the three-entry stuck-loop window can be satisfied by two actual consecutive matching failures ([main.py:39](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/main.py:39), [routing_system.py:142](/tmp/devsopbyai-codegraph-ab-measured-worktrees-20261002/Q1-R1-A-attempt1/routing_system.py:142)).

**Inference / limitation:** the repair branch does not replace `execution_input.dsl` in the visible code; it increments counters and loops. Each dispatch passes the same `execution_input` object to the adapter, so a repaired DSL depends on an upstream hook or external mutation not shown here. No tests were run and no files were modified.
